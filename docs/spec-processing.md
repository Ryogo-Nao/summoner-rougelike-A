# 召喚士ローグライク 処理仕様書

基準の版：v105（2026-11-11）。ここまでを基盤として拡張する。

この文書は「プログラムがどう動くか」をまとめる。何ができるかは [機能仕様書](spec-functions.md)、画面の形は [画面仕様書](spec-screens.md)、数値は [balance.md](balance.md)、決めたことの経緯は [requirements.md](requirements.md) を見る。数値はこの文書に写さず、balance.md の節を指す（写すと食い違うため）。

## 1. 全体の作り

### 1.1 動く環境
| 項目 | 内容 |
|---|---|
| 形 | Web アプリ（PWA）。iPhone の Safari を主な対象にし、縦持ちで遊ぶ |
| 言語・道具 | TypeScript、Vite（ビルド）、Vitest（ゲームの決まりのテスト）、Playwright（画面のテスト） |
| 公開 | main に push すると GitHub Actions が `npm ci` → `npm run build` → `npm test` を流し、GitHub Pages に出す |
| 保存 | 端末のブラウザの localStorage だけ。サーバーはない |
| オフライン | Service Worker（public/sw.js）が、開いたときのページと読み込むファイルを保存する |

### 1.2 フォルダと受け持ち
| フォルダ | 受け持ち | 画面（DOM）に触るか |
|---|---|---|
| src/game | ゲームの決まり。状態・ターン・戦闘・カード・道具・ダンジョン・拠点の保存 | 触らない |
| src/render | キャンバスへの描画。マップ・魔物・演出・ミニマップ | キャンバスだけ |
| src/ui | 画面の部品。拠点・一覧（シート）・確かめの窓・パッド・設定 | 触る |
| src/main.ts | つなぎ役。入力を受けて game を動かし、render と ui に知らせる | 触る |
| public | 絵（art）、アイコン、manifest、sw.js | — |
| tests/unit | ゲームの決まりのテスト（src/game だけを動かす） | — |
| tests/e2e | 画面のテスト（iPhone の WebKit と Chromium） | — |

決まり：src/game は src/ui・src/render を読み込まない。決まりだけを単体で試せるようにするため。拡張するときもこの向きを守る。

## 2. データの形

### 2.1 保存するもの
| localStorage のキー | 中身 | いつ書くか |
|---|---|---|
| `summoner-profile` | `ProfileData`（拠点のすべて） | 拠点で何かを変えるたび、ダンジョンから戻ったとき |
| `summoner-run` | `RunData`（ダンジョンの途中のすべて） | ダンジョンに入ったとき、毎ターンの終わり。終わると消す |
| `summoner-settings` | `Settings`（遊び方の設定） | 設定を変えたとき |

- どれも `version: 1`。項目を足すときは「省いてよい項目（`?`）」として足し、読むときに初めの値を入れる（例：`fromData` の `matk ?? …`）。版を上げずに古いデータを読めるようにする
- 書けないとき（プライベートブラウズなど）は黙って続ける。開いている間は遊べる
- 読めない `summoner-run` は消して拠点から始める

### 2.2 Profile（拠点）
| 項目 | 意味 |
|---|---|
| cards | 持っている仲間すべて（`Card[]`） |
| hand | 連れていく仲間の id（5体まで、選んだ順） |
| bag / warehouse | バッグ（40）と倉庫（9999）の道具 |
| learned | 覚えた魔法（ずっと残る） |
| cleared | 踏破したダンジョンの id |
| shortcuts | ［攻撃］の長押しに登録した道具の種類（3枠） |
| runes | 持っているルーン |
| shopStock | 商店の棚（常設4＋日替わり8） |
| records | 戦績（ダンジョンごと・累計） |
| generation | 何代目か（今はいつも1） |
| notices | 拠点の知らせ（仲間・商店・配合を見たか） |
| bred | 配合で生んだことのある種族（まだの種族は「？？？」） |

### 2.3 GameState（ダンジョンの途中）
| 項目 | 意味 |
|---|---|
| rng | 乱数（状態ごと保存する。同じ種なら同じ結果） |
| dungeon・floor・turn | どのダンジョンの何階・何ターン目か |
| map・explored・visible | 地図、見たことのあるマス、今見えているマス |
| player | 主人公（HP・MP・満腹度・レベル・能力・装備・強化の残りターン・状態異常） |
| cards・storage・pendingCard | 手元のカード（5枚）、保管庫、あふれて待っているカード |
| allies | 召喚中の仲間（カード・位置・向き・指示・状態異常） |
| monsters | 階の魔物 |
| bag・floorItems | バッグと、床に落ちている道具 |
| learned・ranks | 覚えた魔法と、このダンジョンの＋値 |
| runes・stats | 拾ったルーン、倒した数などの記録 |
| cleared・escaped・dead・gaveUp | 終わり方 |
| monsterHouse・revealed | モンスターハウスの部屋、千里の印を使ったか |
| log | ログ（ターン番号付き） |

保存するときは `toData()` で魔物の種族を id に、装備を道具の id に変える。読むときは `fromData()` で戻し、カードと道具の番号が重ならないよう `reserveCardIds`・`reserveItemIds` で次の番号を進める。

### 2.4 表（データ）
| 表 | 場所 | 1行の主な項目 |
|---|---|---|
| 種族 `SPECIES` | monsters.ts | HP・攻撃・防御・魔攻・魔防・属性・経験値・封印のしやすさ・召喚のMP・速さ・特技・強み・成長の型と早さ |
| 相棒 `IZUTSUCHI` | cards.ts | 種族と同じ形。表には入れない |
| 道具 `ITEMS` | items.ts | 名前・読み・説明・効き目（食べ物・回復・装備・杖・魔導書・矢・印・星・袋）・値打ち |
| ダンジョン `DUNGEONS` | dungeons.ts | 階の数・前に踏破がいるダンジョン・魔物の表・道具の表・ルーン・モンスターハウス・見た目 |
| 魔法 `SPELLS` | state.ts | 名前・MP |
| 性格 `PERSONALITIES` | cards.ts | 上がる能力・下がる能力 |
| 配合の組み合わせ `RECIPES` | fusion.ts | 親の種族2つ → 子の種族 |
| 商店の品 `STOCK_POOL` | shop.ts | 品・出やすさ・挑めるようになっているべきダンジョン |

## 3. 起動と画面の切り替え（main.ts）

1. `loadProfile()`・`loadSettings()` で拠点と設定を読む
2. `summoner-run` があれば `GameState.fromData` で続きから始める。なければ拠点（`BaseScreen.open`）を出す
3. はりつけ・昏睡のまま閉じていたら、続きのターンを自動で進める
4. 公開した版だけ Service Worker を登録する（開発中は使わない）

| 切り替え | 処理 |
|---|---|
| 拠点 → ダンジョン | `startRun(dungeonId)`：`loadoutOf(profile)` で持ち物を写し、`new GameState(seed, loadout, dungeonId)`。最初のログを入れて保存し、拠点を閉じて階の名前を出す |
| ダンジョン → 拠点 | `endRun()`：`returnToBase(profile, state)` で持ち帰り、結果の知らせ（踏破・離脱・あきらめた・力つきた、失ったもの、ルーン、挑めるようになったダンジョン）を確かめの窓で出す。［拠点へ］で拠点を開く |

- `?seed=数字` を付けて開くと、毎回同じダンジョンになる（試すとき用）
- 開発中だけ、ブラウザのコンソールから `game`・`renderer`・`profile` に触れる

## 4. 1ターンの流れ

### 4.1 入力から描画まで
```
入力（パッド・ボタン・一覧）
  → acceptsInput()：場面の再生中・窓や一覧が開いている・終わったあとは受け付けない
  → GameState の行動（tryMove・attack・cast・useItem・throwItem・summon・wait など）
       beginAction()：turn+1、場面とポップアップを空にする
       主人公の行動
       endTurn()
  → afterAction()
       playScenes()：起きた場面を順に再生（render）
       redraw()：HUD とマップを描き直す
       あふれたカードがあれば「仲間がいっぱい」の一覧
       力つきた・離脱したら endRun()
       saveRun()：毎ターン保存
       はりつけ・昏睡なら 0.3秒後に自動で足踏み
```
- 振り向くだけ・ターンを使わない操作（見通し・並べ替え・登録など）は `beginAction` を通らない

### 4.2 endTurn の順
1. 転送の印で出た・踏破したなら、ここで終わる（誰も動かない）
2. `showOwnAction()`：主人公の行動で出た数字（回復など）を、ほかの者が動く前の場面にする
3. 視界を作り直し、モンスターハウスの部屋に入ったか確かめる（入ったら眠っている魔物が起きる）
4. 鈍足の休みの切り替え（2ターンに1回休む）
5. 仲間が動く：主人公に近い仲間から。速さが「速い」なら2回、「鈍足」は休みのターンに0回
6. 魔物が動く：同じく速さの回数だけ。主人公が倒れたらやめる
7. 満腹度を減らす（10ターンに1。0ならHPが減る）
8. HPの自然回復（端数は持ち越す）
9. 強化の残りターンと状態異常を1減らす
10. 40ターンごとに、見えないところへ魔物を1体足す
11. 視界を作り直す

### 4.3 場面（Scene）
- 攻撃・魔法・投げる・撃つなど、見せたいことは `scene(attacker, toward, act, fx)` で包む。`act` の中でダメージなどを決め、その前後のログ番号・主人公のHP・ポップアップを場面に記録する
- 画面は `takeScenes()` で取り出して順に再生し、場面ごとに「その時点のHPとログ」を出す（あとの攻撃の結果が先に見えないように）
- 段は 構える → 飛ぶ → 当たる。長さは render/effects.ts。設定の速さ（ふつう・速い・最小）で縮め、1回の行動の合計は 2.6秒まで（こえたら全体を速める）

## 5. 主な計算

| 計算 | 式・決まり | 数値の場所 |
|---|---|---|
| ダメージ | 攻撃力 × 16 ÷ (16 + 防御力) × 属性の倍率 × 乱数(0.88〜1.12)。四捨五入、最低1 | combat.ts、balance.md 3.1 |
| 魔法のダメージ | 上の式の攻撃力を威力（魔攻から）、防御力を魔防に変える | balance.md 3.6 |
| 命中 | 通常攻撃・矢は 90％。魔法・火を吐く・いかずちは必ず当たる | balance.md 3.2 |
| 属性 | 強い相手へ ×1.5、同じ属性か相手が強い属性なら ×2/3、無は ×1 | elements.ts、balance.md 3.7 |
| 受けるダメージの強み | sturdy は全部 ×1/2、armored は物理（通常攻撃・舌や触手・矢）だけ ×2/3。どちらも最低1 | monsters.ts `sturdyDamage`、balance.md 4.6 |
| 要塞の星・守り | 受けるダメージを減らす（`fortified`・`guarded`・`warded`） | balance.md 6.6・2.1 |
| 経験値の山分け | 主人公と召喚中の仲間で等分。とどめを刺した者は1.5倍。毒で倒れたときは上乗せなし | balance.md 4.3 |
| レベル | 累計経験値の表（主人公は ×1.2、仲間は ×2。1段は 7000 まで）。最大99 | combat.ts、balance.md 1.3・4.2 |
| 仲間の能力 | （Lv1の値 ＋ 伸び × 成長の型 × 成長の早さ）× 性格 ＋ 足し算の補正。配合回数（イヅツチは転生回数）で伸びが増える（`growthRate`） | cards.ts `cardStats`、balance.md 4.2 |
| 敵の能力 | Lv1 は表の値。そこから仲間と同じ伸び方 | cards.ts `monsterStats`、balance.md 4.5 |
| 封印の成功率 | 残りHPの割合で基本の確率を1〜5倍 | cards.ts `captureChance`、requirements.md 5.2 |
| カードを落とす率 | 封印のしやすさ × 0.1 | balance.md 4.1 |

## 6. 動きの決まり

### 6.1 魔物（monsterAct）
上から順に、当てはまったものを1つだけする。
1. はりつけ・昏睡・モンスターハウスで眠っている → 動かない
2. 火を吐く魔物で、まっすぐ4マス以内に主人公か仲間がいる → ときどき吐く（両方いれば 3:1 で主人公）
3. 攻撃が届く相手（隣か、舌・触手の2マス先）がいる → 攻撃（両方いれば 3:1 で主人公）。混乱していれば8方向からでたらめ、ふらふらは半分で行動を失う。2回攻撃は2回
4. ふらふら → 半分の確率ででたらめに1歩
5. 最後に主人公を見た場所か、うろつく行き先へ1歩（幅優先探索）。たどり着けなければ行き先を選び直す

### 6.2 仲間（allyAct）
1. はりつけ・昏睡 → 動かない
2. 指示が「逃げる」で、4マス以内に魔物が見える → 離れる方へ1歩
3. 隣に魔物がいる（眠っている・はりつけの魔物は狙わない） → HPの少ない魔物を攻撃。2回攻撃、毒・混乱などの特技も
4. 相棒は 2マス先へ「いかずち」（確率）。火を吐く仲間は 4マス以内へ火（確率）
5. 「待機」 → ここで終わる
6. 離れたところから自分を攻撃してきた魔物 → 近づく
7. 「突撃」 → いちばん近い見えている魔物へ。2マス手前で待つ（ほかが戦っていれば加勢）
8. 主人公を離れたところから攻撃してきた魔物 → 近づく
9. 主人公についていく（歩数の表で近づく）

### 6.3 階に入る（enterFloor）
1. 地図を作る（dungeon.ts `generateFloor`：44×30、4×3 の区画の7〜10個に部屋、全域木＋足した通路で輪を作る）
2. 召喚中の仲間を主人公のまわりに置く（置けなければカードに戻す）
3. 主人公のいない部屋に魔物を 5〜7体（`pickMonster`）
4. 道具（`randomItem`）とルーン（`randomRune`）を置く
5. 決まった階から、確率でモンスターハウス（眠った魔物と道具を足す）

### 6.4 出る魔物と道具の選び方（dungeons.ts）
- 魔物：その階に出る行（`floors` の幅）から選ぶ。`tiered` のダンジョンは、`strongShare(floor)` の割合で強い魔物の行か弱い魔物の行かを先に決める（balance.md 7.5）
- 道具：その階に出る行から重みで選ぶ。毒にする魔物がいないダンジョンでは毒消し草、混乱させる魔物がいないダンジョンではキツケソウを外す
- ルーン：山の数と額の幅。深い階ほど増える

## 7. 拠点の処理（profile.ts・fusion.ts・shop.ts）

| 処理 | 関数 | 中身 |
|---|---|---|
| 持ち出し | `loadoutOf` | 連れていく仲間（選んだ順に5体）・バッグ・覚えた魔法・登録を写す。最初の3体は召喚した状態で入る |
| 持ち帰り | `returnToBase` | 記録を足す。力つきたら、ここで仲間にした魔物と、バッグの半分と、拾ったルーンの半分を失う。残った仲間はHP満タンで戻り、新しい仲間は一覧の後ろに付く。踏破なら `cleared` に足す。棚を並べ直し、知らせを立てる |
| あきらめた | `giveUpToBase` | ダンジョンに入る前の拠点に戻す（ダンジョンで得たものは残らない）。そのうえで持っていった道具の半分と、拾ったルーンを失う |
| 半分を失う | `halveBag` | 聖なる袋（と中身）は失わない。残った聖なる袋は 30％でふつうの袋に戻る |
| 配合 | `fuse` | Lv10 以上の2体・配合の書・1000ルーン。子の種族（組み合わせ表か親の種族）、性格（親の性格が 35％ずつ）、足し算（親の能力の 5％）、配合回数 |
| 転生 | `rebirth` | イヅツチを Lv1 に戻し、足し算と性格を変え、転生回数 +1。合わせた魔物はいなくなる |
| 棚 | `rollStock` | 常設（薬草2・パン2）＋ 日替わり8（重みで選び、重なりあり。挑めるダンジョンの品だけ） |
| 買う・売る | `buy`・`sell` | 買い値は値打ち、売り値は 1/3。中身の入った袋は売れない |

## 8. 描画（render）

- キャンバス1枚にマップを描く。画面に映すのは主人公を中心にした範囲（マス数は renderer.ts）
- 床と壁は階に入ったときに1枚の絵にまとめ、毎回は見えているところを写す
- 歩く動き（約0.12秒・小さく跳ねる）と、立っているときの息づかいのため、ふだんは1秒に20回、歩いている間は毎回描く
- 場面の再生中は `Playback` を渡し、構える・飛ぶ・当たるの段に合わせて動かす
- 絵は public/art の PNG。読み込めないときは絵文字で描く

## 9. 入力（ui/pad.ts・quick.ts）

| 入力 | 処理 |
|---|---|
| パッドを押す | 押した瞬間に1回。0.28秒押し続けるとダッシュ（0.07秒ごと）。止まるところは main（`dashShouldStop`） |
| 指を滑らせる | 指の下のボタンに切り替わる |
| ［攻撃］を短く押す | 離したときに攻撃 |
| ［攻撃］を長押し | 0.3秒で扇（3枠）を出し、離した枠の道具を使う |
| 右のボタン | iPhone の長押しのルーペを止めるため、click ではなく pointerdown で受ける（確かめの窓は click） |

## 10. オフライン（public/sw.js）

- 入れたとき：ページと、ページが読み込むファイル（ビルドで名前が変わる）、manifest、アイコンを保存する。前のビルドのファイルは消す
- 読むとき：通信できれば新しいものを取りに行って保存し直す。できなければ保存したものを返す
- `CACHE` の名前は、保存の仕方を変えたとき・版を出すときに上げる（今は summoner-v105）

## 11. テスト

| 種類 | 動かし方 | 中身 |
|---|---|---|
| 決まりのテスト | `npm test`（テストの型チェック込み） | tests/unit。種を固定した GameState で戦闘・道具・ダンジョンなどを確かめる。helpers.ts の `emptyState`・`placeMonster` を使う |
| 画面のテスト | `npx playwright test` | tests/e2e。iPhone の WebKit と Chromium。localStorage の `summoner-run` を書き換えて、確かめたい状態を作れる |
| 項目と結果 | docs/test-plan.md・test-results.md | F（機能）・P（性能）・N（非機能）の番号 |

## 12. 拡張するときの手順

| 足すもの | 触るところ |
|---|---|
| 魔物 | monsters.ts の `SPECIES` に1行。絵（public/art）・顔・台帳（characters.ts、docs/characters.md）。出すダンジョンの `monsters` に行を足す。配合で生むなら fusion.ts の `RECIPES` |
| ダンジョン | dungeons.ts に `Dungeon` を1つ足して `DUNGEONS` に入れる。`requires` で前のダンジョンを決める。強い・弱いを分けるなら `tiered: true` と `strong()`。見た目は `theme` |
| 道具 | items.ts の `ItemKind` と `ITEMS`。使ったときの処理は state.ts の `useItem`。落とすダンジョンの `items`、商店なら shop.ts の `STOCK_POOL` |
| 魔法 | state.ts の `SPELLS`・`SPELL_ELEMENT`・`spellArea`、演出は render/spells.ts、絵は screens.ts の `SPELL_ART` |
| 特技 | monsters.ts の `special`、state.ts の `afflict`・`monsterAct`・`allyAct` |
| 保存する項目 | `RunData`・`ProfileData` に省いてよい項目として足し、読むときに初めの値を入れる。`version` は上げない |
| 拠点の画面 | base.ts の `View`・`NAV`・`render` |
| ダンジョンの一覧 | screens.ts に `openXxxSheet`。道具の一覧は `lines: true` と `groupItems` でバッグと同じ形にする |

どれも、数値を balance.md に、決めたことを requirements.md に書き、テストの項目を test-plan.md に足す。
