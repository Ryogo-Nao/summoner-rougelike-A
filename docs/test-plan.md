# テスト計画（2026-11-07）

v60 までの改修で、一度まとめてテストする。項目は「機能」「性能」「非機能」の3つに分ける。
できるものは自動にし、iPhone の実機でしか確かめられないものだけを手で確かめる。

## 0. 自動テストの動かし方

| コマンド | 中身 | かかる時間の目安 |
|---|---|---|
| `npm test` | ゲームの決まりのテスト（tests/unit）と、性能のテスト（tests/perf）。Vitest で、ブラウザなしで動く | 30秒ほど |
| `npm run test:e2e` | 画面のテスト（tests/e2e）。ビルドしたものを Playwright で開き、iPhone の大きさ（390×844、WebKit＝Safari と同じ仕組み）と Chrome で操作する | 1〜3分 |
| `npm run test:all` | 上の2つを続けて行う | |

- 初めて画面のテストを動かすときは、`npx playwright install webkit chromium` でブラウザを入れておく
- GitHub に push すると、公開の前に `npm test` が動く。落ちたら公開しない（画面のテストは手元で動かす）
- 乱数は決まった種（seed）を使うので、何度動かしても同じ結果になる

### 確かめ方の印
- **U**：ゲームの決まりのテスト（tests/unit）
- **P**：性能のテスト（tests/perf）
- **E**：画面のテスト（tests/e2e）
- **手**：iPhone の実機で手で確かめる

## 2. 性能のテスト

| ID | 確かめること | 目安 | 方法 |
|---|---|---|---|
| P-01 | 1ターンの計算（魔物20体がいる階） | 平均 2ms 以下 | P |
| P-02 | 1階のマップを作る時間 | 平均 20ms 以下 | P |
| P-03 | ダンジョンの途中の保存・読み込み | それぞれ 20ms 以下 | P |
| P-04 | 保存データの大きさ（ダンジョンの途中・拠点に仲間100体と道具300個） | 300KB 以下（iPhone の保存の上限は約5MB） | P |
| P-05 | 長く遊んでも止まらない（3000ターンをでたらめに操作）。ログは100行を超えない | エラーなし | P |
| P-06 | 公開するファイルの大きさ（JS・CSS） | JS は gzip で 100KB 以下 | P |
| P-07 | ページを開いてから拠点が出るまで | 3秒以内（手元のサーバー） | E |
| P-08 | ダンジョンの描画で、止まるフレーム（50ms 以上かかったフレーム） | 5％未満（テストのブラウザは画面に出さないので、60fps かどうかは実機の P-09 で見る） | E |
| P-09 | 実機での動きの重さ・電池の減り | 気にならない | 手 |

## 3. 非機能のテスト

| ID | 確かめること | 方法 |
|---|---|---|
| N-01 | iPhone の幅（375・390・430）で、どの画面も横にはみ出さない | E |
| N-02 | 画面を開いて操作しても、コンソールにエラーが出ない | E |

| N-05 | 保存できない環境（プライベートブラウズなど）でも遊べる | U |
| N-06 | 前の版の保存データ（性格のないカード・足りない項目）を読み込める | U |
| N-07 | 文字を打つ欄の字は16px 以上（iPhone で画面が拡大されない） | E |
| N-08 | ボタンの大きさが 32px 以上（指で押せる） | E |
| N-09 | API キーなどの秘密が、ソースと公開するファイルに入っていない | U |
| N-10 | 画面に「undefined」「NaN」「[object Object]」が出ない | E |
| N-11 | ホーム画面に追加したときの見え方、ノッチ・ホームバーとの重なり、ダークモード | 手 |
